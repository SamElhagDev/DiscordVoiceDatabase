# Implementation Plan: Performance Logging

**Branch**: `003-performance-logging` | **Date**: 2026-05-20 | **Spec**: [spec.md](specs/003-performance-logging/spec.md)
**Input**: Feature specification from `specs/003-performance-logging/spec.md`

## Summary

Add a `perf_logs` SQLite table that stores wall-clock completion times for each
pipeline stage (remux, transcribe, rotate), split by method and linked to the
segment that triggered the work. A new `//perfstats` hybrid command queries
running averages normalised to a 60-second audio segment. Cleanup cascades
through the existing retention system.

## Technical Context

**Language/Version**: Python 3.11+
**Primary Dependencies**: discord.py, aiosqlite (both existing)
**Storage**: SQLite — new `perf_logs` table; schema.sql + IF NOT EXISTS
**Testing**: Manual (bot testing in Discord; verify perf rows appear after recording, verify `//perfstats` output)
**Target Platform**: Windows 11 self-hosted
**Project Type**: Discord bot — cog-based architecture
**Performance Goals**: Perf log writes must complete in <10ms; must not block audio receive
**Constraints**: DB writes serialised by existing `_lock`; one extra write per segment per method (up to 3 writes per segment)
**Scale/Scope**: 6 files modified, ~100 lines of new code

## Implementation Details

### Change 1: Schema — `database/schema.sql`

Append the `perf_logs` table and two indexes after the existing
`recording_settings` table. Uses `IF NOT EXISTS` so it's safe for both
new installs and existing ones.

### Change 2: Database methods — `database/__init__.py`

Add three methods to `DatabaseManager`:
- `log_perf(segment_id, method, duration_sec, audio_duration_sec)` — INSERT
- `get_perf_stats(since_ts, since_24h_ts)` — aggregate query grouped by method
- `delete_perf_logs_by_segment_ids(segment_ids)` — bulk DELETE for retention

### Change 3: Recorder timers — `recording/recorder.py`

**`_rotate_user`**: Wrap the work between lock release and remux enqueue
with `time.time()`. Compute `audio_dur = end_ts - start_ts`. Call
`db.log_perf(segment_id, "rotate", ...)`. Pass `audio_dur` to the remux
queue so the remux worker can log it without re-querying.

**`_remux_worker`**: Wrap the `asyncio.to_thread(_remux_pcm_to_ogg, ...)`
call. Audio duration comes from the queue item (added in Change 3 above).
Call `db.log_perf(segment_id, "remux", ...)`. Pass `audio_dur` to
`transcriber.enqueue` so the transcriber can log it.

### Change 4: Transcriber timer — `recording/transcriber.py`

Extend `enqueue` to accept `audio_duration: float`. In `_worker`, wrap the
`asyncio.to_thread(self._transcribe, ogg_path)` call and pass `audio_duration`
to `db.log_perf(segment_id, "transcribe", ...)`.

### Change 5: Retention cleanup — `recording/cleanup.py`

In `run_cleanup`, call `db.delete_perf_logs_by_segment_ids(ids)` before
`db.delete_segments_by_ids(ids)` so perf rows are removed atomically with
their parent segments.

### Change 6: Command — `cogs/voicedatabase.py`

Add `//perfstats` hybrid command. Takes optional `days` (default 7). Calls
`db.get_perf_stats(since_ts, since_24h_ts)`. Formats results into a Discord
embed with per-method rows and a pipeline total in the footer. Handles the
empty-data edge case with an ephemeral message.

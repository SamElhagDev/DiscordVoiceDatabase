# Implementation Plan: `//listtext` Command

**Branch**: `001-add-listtext-command` | **Date**: 2026-05-19 | **Spec**: [spec.md](specs/001-add-listtext-command/spec.md)
**Input**: Feature specification from `specs/001-add-listtext-command/spec.md`

## Summary

Add a `//listtext` hybrid command that reuses the existing segment listing and dropdown selection UI from `//listclips`, but instead of triggering audio download/playback, posts the selected segment's transcript text as an embed in the channel. This requires extending `_ClipSelectView` with a third mode (`"text"`) and adding one new command method — all changes confined to `cogs/voicedatabase.py`.

## Implementation Details

### Change 1: Add `mode="text"` handling to `_ClipSelectView`

**File**: `cogs/voicedatabase.py`
**Location**: `_ClipSelectView._rebuild_items` (placeholder text) and `_ClipSelectView.on_select` (selection handler)

- In `_rebuild_items`: add placeholder text for `mode="text"` → "Pick a segment to view transcript..."
- In `build_embed`: update footer action text for `mode="text"` → "view its transcript"
- In `on_select`: add an `elif self.mode == "text"` branch before the existing `self.mode == "download"` check that:
  1. Extracts transcript from `seg[8]`
  2. Handles missing/blank transcript with ephemeral error
  3. Posts the transcript as plain text (no embed) so other bots can read `message.content`
  4. Splits into multiple messages if transcript exceeds 2000 chars
  5. Sends via `interaction.response.send_message` (first chunk) and `interaction.followup.send` (remaining chunks)

### Change 2: Add `listtext` command method

**File**: `cogs/voicedatabase.py`
**Location**: After the existing `list_clips` method

Mirrors `list_clips` exactly (same parameters, same query, same "Blank" filtering), but passes `mode="text"` to `_ClipSelectView`.
